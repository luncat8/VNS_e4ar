# VNS_e4ar — Visual Novella Scroll Engine — Plan Overview

## Concept
Prose scrolls; background images ride with it like train wagons. A wagon
moves 1:1 with its own DOM text position, sticks ("parks") at the viewport
edge when it reaches it, and leaves only when the next wagon below collides
with its bottom and pushes it out. Page theme (colours, classes) morphs
between scroll anchors so a chapter change reads like a sunset or a door
opening onto a bright room — interactive, never a blink. Inert
`<script type="txt" event=...>` blocks fire on scroll states.

Everything is free-placed in the DOM: no strict `<section>` tree, no required
wrapper, no renpy-like DSL. Backgrounds are not owned by sections — an author
may keep one across sections or introduce a new one between two text lines.
`file://` friendly, no build, no modules, no network, classic `<script>` tags.

## Files
| file | role | plan |
|---|---|---|
| `index.html` | demo/QA shell: form + `#app` + `<script src>` tags | 0.1 |
| `harness.css` | author-side look of the demo: type, panels, QA classes | 0.1 |
| `harness.js` | content generator, diagnostics, auto-scroll, QA probes | 0.1 |
| `vns.js` | engine: core loop + shared anchors + wagons + morph + events | 0.2–0.4 |
| `test/math.js` | `node test/math.js` — pure math, no DOM | 0.2–0.4 |

`vns.js` injects its own `<style>` so it works in any host page; the host only
declares `.bg` images and optional `data-*`. Every `.js` file is a classic
script that is also `require()`-able under Node
(`if (typeof module !== 'undefined') module.exports = VNS;`) with zero DOM
touch at load time, so all math is unit-testable headless.

## Plan Sequence — implement in order
1. **0.1 Test harness** — generator + diagnostics + QA probes. Lands first:
   it is the manual QA surface for every later plan and must work with no
   engine present (`?engine=0`) so that "engine absent" and "engine wrong"
   are visually different states. Depends on nothing.
2. **0.2 Wagon engine** — the core. Also owns the shared plumbing every later
   plan reuses: one rAF loop, one anchor-measurement pass, `refresh()`,
   `data-*` authoring API. Park/push math, size modes, `data-dir`, reversible.
3. **0.3 Style morph** — second `VNS.use()` subscriber. Lerps colours and swaps
   classes between `[data-bg]/[data-fg]/[data-style]` anchors. No own loop, no
   own listener. Works with wagons off.
4. **0.4 Script events** — third subscriber. Edge-triggered
   `view|center|parked|end|skip` on inert `script[type=txt]`. `parked` reads
   wagon state, degrades to `view` when wagons are off.

Each plan is a self-contained spec: DOM contract, algorithm, test matrix,
acceptance criteria. Implement one, pass its criteria, then next, then
`git mv` it to `archive/` (AGENTS).

## Architecture rule: one core, three subscribers
`vns.js` = `core` + three controllers registered as `VNS.use({measure, frame})`.
Scroll, resize, rAF scheduling, dirty flags and anchor Y measurement live only
in `core`. A controller never adds a scroll listener, never runs its own rAF,
never measures layout in `frame()`. If `core` is absent (engine disabled, JS
off) every controller is inert and the page is still readable prose.

## Layout Contract (hard requirement)
- `#vns-layer` — `position:fixed;inset:0;contain:layout paint`, direct child of
  `<body>`, painted behind `#app`. All wagons live here as
  `position:absolute;left:0;top:0` + `transform:translate3d()`.
- Wagons are **hoisted** out of their author position into `#vns-layer`; a
  zero-size absolutely-positioned marker `<i class="vns-a vns-w">` stays at the
  original spot as the anchor. Hoisting + absolute (not fixed) positioning is
  what makes the engine immune to ancestor `transform`/`filter`/`will-change`
  /`contain`, which silently re-parent `position:fixed` and are the #1 way a
  wagon engine "randomly" breaks in real markup.
- No author or harness CSS may put `transform`, `filter`, `will-change` or
  `contain:paint` on an element that has a `position:fixed` descendant.
  `#app` may be filtered (wagons are outside it); the layer must not be.
- `#app{position:relative;z-index:1}` and page colour on `html` (never on
  `#app`) so wagons at `z-index:0` stay visible behind transparent text.
- Document order is logical order for wagons, style anchors and scripts alike.

## Global Invariants (all plans)
- Pure function of `scrollY`: same `scrollY` ⇒ same transform, colour, class —
  independent of direction and history. No hysteresis, no smoothing filters,
  no springs. Reversibility is a theorem of the math, not a test to hope for.
- Continuous: no wagon may jump more than one frame's scroll delta.
- Never overlap while parked; the push chain is a *ceiling*, so a wagon is
  never placed below its own anchor.
- No layout writes ever: after `measure`, the engine writes `transform` and CSS
  custom properties only. `frame()` does zero `getBoundingClientRect`,
  zero `offsetTop`, zero reads.
- No allocations in `frame()`: preallocated typed arrays, reused scratch, no
  `{}`, `[]`, closures, or string concat unless the value actually changed.
- O(N) per frame with N = anchors, and N is small by construction (one wagon
  per chapter-ish), so no spatial indexing.
- Style: single tab indent, LF, early returns, flat helpers,
  `const $ = id => document.getElementById(id)`, comments only where a decision
  needs a `why`.

## How To Verify
`python3 -m http.server` or open `index.html` via `file://` — both must work.
Harness presets + controls rebuild content; `?engine=0` shows the no-engine
baseline. Scroll slow/fast/both ways; watch the diagnostics panel.
`node test/run.js` runs every gate: `test/math.js` (pure scroll/colour/event math,
no dependencies — the one that must stay green), `test/dom.js` (engine mechanics
under a synthetic block layout) and `test/page.js` (loads the real `index.html` in
jsdom: id wiring, hoisting, QA probes running) and `test/assets.js` (every inline
style is legal CSS, every generated SVG data URI is well-formed XML sized like its
`data-size`, the injected engine CSS has a rule per mode, and the harness CSS keeps
the DOM contract). The latter two need
`npm i jsdom`, dev-only — the engine ships with no deps, no build and no modules.
QA buttons in the panel execute
0.2–0.4 acceptance criteria mechanically (reversibility, no-overlap,
anchor-align, jump) and print PASS/FAIL. Each plan's Acceptance Criteria is
the gate for archiving it.

## Out Of Scope
- Build step, modules, npm, network images, polyfills, legacy browsers.
- Parallax speed factors (wagons never move faster/slower than their text,
  except lateral `data-dir` exit which is a different axis).
- Timeline/GUI editor, audio, typewriter text reveal, save state, i18n,
  virtualized DOM, pinch-zoom beyond `resize` recompute.
