# 0.4 — Scroll Script Event System

## Goal
Declarative `<script type="txt">` blocks that fire at precise scroll
states — view, centre, parked, end, skip — without author writing scroll
listeners. Lets visual novella trigger console logs, state changes, or
light DOM mutations per chapter while staying `file://` safe.

## Non-goals
- Not `eval` of arbitrary modules; keep to tiny `type="txt"` snippets
  (plain JS) executed in page scope via `Function`.
- Not a renpy-like DSL. Author writes normal JS; engine decides *when*
  to run it.
- No per-frame script execution — only edge-triggered once per crossing.

## DOM Contract
```html
<section id="ch3">
  <div class="bg" style="background-image: ..."></div>
  <h2>3</h2>
  <script type="txt" event="view">console.log("section view (bottom of screen)")</script>
  <script type="txt" event="center">console.log("section reach center")</script>
  <script type="txt" event="parked">console.log("wagon parked at top")</script>
  <script type="txt" event="end">console.log("section out of screen")</script>
  <script type="txt" event="skip">console.log("section skipped")</script>
</section>
```
- `type="txt"` — inert script, not executed by browser. Engine collects
  via `querySelectorAll('script[type="txt"]')`.
- `event` attribute — one of:
  - `view` — anchor enters viewport (bottom edge crosses `Hv`).
  - `parked` — associated wagon parks at `top==0` (if element has/near
    `.bg`; otherwise alias to `view`).
  - `center` — anchor crosses viewport centre (`Hv/2`).
  - `end` — anchor leaves viewport past top (`top+H < 0` or section
    bottom above 0).
  - `skip` — anchor was never in `view`/`center` but scroll is now
    after it (`scrollY > Y+H`). Fires once instead of view/center.
- Association: script belongs to its closest ancestor `<section>` or
  preceding `.bg` in document order (nearest `Y` anchor). If free-floating
  outside sections, `Y` = script element's placeholder offset.
- Multiple scripts per event per anchor allowed; executed in DOM order.

## Architecture
`ScriptEvents` controller shares rAF with 0.2/0.3 (single rAF loop).
Pre-allocated arrays: `Y_e[], H_e[], state[], firedSkip[]`, `code[]`
(compiled `Function`).

State per anchor: bitmask `SEEN_VIEW|SEEN_CENTER|SEEN_PARKED|SEEN_END`.

Per frame after computing `top[i]` (from 0.2) and `scrollY`:
```
for each anchor i:
  inView  = Y[i]-scrollY < Hv && Y[i]-scrollY+H[i] > 0
  atCenter= Y[i]-scrollY < Hv/2 && Y[i]-scrollY+H[i] > Hv/2
  parked  = topAssoc[i]==0 && free[i]<=0   // from wagon engine if present
  past    = Y[i]-scrollY+H[i] < 0

  if(inView && !state[i].view)  { fire("view", i);  state[i].view=1 }
  if(atCenter&& !state[i].center){ fire("center",i); state[i].center=1 }
  if(parked && !state[i].parked) { fire("parked",i); state[i].parked=1 }
  if(past   && !state[i].end)    { fire("end", i);   state[i].end=1 }

  // skip: if past && !view then view was skipped (fast scroll)
  if(past && !state[i].view && !firedSkip[i]) { fire("skip",i); firedSkip[i]=1 }

  // reverse scroll reset: if anchor re-enters from opposite side,
  // allow re-fire? Policy: events are one-shot per forward pass;
  // on reverse past threshold, clear flags so re-scrolling forward
  // fires again. Implement hysteresis 40 px to avoid chatter.
  if(!inView && state[i].view && Y[i]-scrollY > Hv+40) state[i].view=0
  // similar for center/end with margins
```
`fire(event,i)`:
- Lookup scripts for `(anchor i, event)`.
- Execute `Function('"use strict";'+code)()` in page scope but sandboxed:
  expose `console`, `document`, `window`, `detail={anchor, event, Y, scrollY}`.
  No allocations per fire beyond call.
- Mark `fired` to avoid repeat until reset; `skip` never fires if `view`
  already fired.

Compilation at `init`/`refresh`:
```
for each script el:
  code = el.textContent.trim()
  if(!code) continue
  fn = new Function(code) // guarded try/catch
  store fn + event + anchorIdx
  el.remove() // prevent double exec, keep placeholder comment
```
Guard: wrap `new Function` in try/catch, log error once, continue.

## Integration
- If 0.2 wagons absent, `parked` event falls back to `view` (never fires
  separately) — documented.
- Shares placeholder `Y` measurement so scripts free-placed between text
  lines have correct trigger point.
- Free DOM placement: collect scripts globally, sort by `Y`, not by
  section tree traversal, so author can interleave.

## Performance & Style
- Single tab indent, flat helpers `isInView()`, `fire()`.
- No closures/objects per frame; state in `Uint8Array`, `Int32Array`.
- Scroll listener passive, rAF only.
- Classic `<script>` tag, no modules, `file://` safe.

## Test Matrix (uses 0.1 harness)
- Slow scroll top→bottom: observe console sequence
  `view→center→parked→end` per chapter, no duplicates.
- Fast flick to bottom (skip): chapters never entering view fire `skip`
  once plus `end`, but not `view`/`center`. Check panel logs count.
- Reverse scroll bottom→top: flags reset with hysteresis, forward pass
  fires again.
- Anchor with multiple scripts same event: both run in order.
- Free-placed script between text lines (outside section): fires at its
  own Y, independent of section bounds.
- Syntax error in one script: console error, other scripts still fire.
- No wagon present: `parked` never fires (or fires as `view` if
  fallback configured — assert one behaviour and test).

## Acceptance Criteria
- [ ] Each declared event fires exactly once per forward pass at the
  documented viewport threshold (±2 px).
- [ ] `skip` fires only if `view` was not fired before `past`.
- [ ] Reverse scroll does not fire new events, but re-entering and
  re-passing forward fires again (reset after +40 px margin).
- [ ] Script errors isolated; engine continues, wagon/style engines
  unaffected.
- [ ] All events work with both section-bound and free-floating scripts.
- [ ] `file://` open: scripts execute without CSP/module issues.

## Pitfalls
- Do not use `IntersectionObserver` — `file://` and precise `parked`
  (transform-based, not layout) make it unreliable; use scrollY math.
- Do not fire events inside scroll handler synchronously; batch in rAF
  after wagon `top[]` computed so `parked` is accurate.
- Avoid double-fire on jitter: hysteresis margin on reset, not on set.
- Remember to `el.remove()` after compile so browser never tries to
  execute `type="txt"` on navigation.
