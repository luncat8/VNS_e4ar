# 0.4 — Scroll Script Event System

## Goal
Declarative `<script type="txt" event="…">` blocks that fire at exact scroll
states — `view`, `center`, `parked`, `end`, `skip` — so a visual novella can
log, flip state, or mutate light DOM per chapter without writing a single
scroll listener. `file://` safe, inert until the engine runs them.

## Non-goals
- Not a DSL, not renpy-like: the body is plain JS. The engine only decides
  *when*.
- No per-frame execution: events are edge-triggered, once per crossing.
- No async, no `import`, no modules, no promise chains inside snippets.
- Not an animation trigger system (that is 0.3's job, driven continuously).

## DOM Contract
```html
<section id="ch3">
  <div class="bg" style="background-image:url(…)"></div>
  <h2>3</h2>
  <script type="txt" event="view">VNSlog("ch3 view (bottom of screen)")</script>
  <script type="txt" event="center,parked">VNSlog("ch3 centre and parked")</script>
  <script type="txt" event="end">document.documentElement.dataset.chapter="3"</script>
  <script type="txt" event="skip">VNSlog("ch3 skipped by fast scroll")</script>
</section>
```
- `type="txt"` ⇒ the browser treats it as a data block and never executes it
  (that is the whole trick; no CSP-unsafe `eval` of markup at parse time).
- `event` is a comma-separated list — `event="center,parked"` registers the
  same body on two events. One body per event keeps authors honest about which
  threshold they mean.
- Events, relative to the script's own anchor `Y` and height `H` (its marker,
  see below), with `c = scrollY`, `vh = innerHeight`:
  - `view` — overlaps the viewport: `d < vh && d + H >= 0`.
  - `center` — crosses the reading line while still on screen:
    `d < vh * 0.5 && d + H >= 0`.
  - `parked` — its wagon is pinned at the edge: `pos[w] == 0 && free[w] <= 0`.
  - `end` — left past the top: `Y - c + H < 0`.
  - `skip` — `end` became true while `view` had never fired: the user jumped
    past the topic, so run the fallback/default actions.
- Association: a script's `parked` target is the **last wagon whose marker Y is
  ≤ the script's Y** (`lastIndexLE` over wagon anchors) — i.e. the picture that
  is on screen where the script sits, whether or not it is inside a section.
  No such wagon, or wagons disabled ⇒ `parked` never fires (fallback alias to
  `view` only when `VNS.options.parkedAsView = 1`; the test asserts one
  behaviour, not both at once).
- Multiple scripts per event per anchor: all run, in document order.
- Free-floating scripts (outside any section) are first-class: the trigger point
  is the script's own position, not a parent's.

## Anchor Measurement
`<script>` is `display:none`, so `getBoundingClientRect()` is a zero rect at the
document origin — measuring the element directly is not just imprecise, it is
meaningless. Contract: reuse `core`'s marker helper (`<i class="vns-a vns-e">`
inserted before the script, `VNS.anchorY(el)`), which also fixes the identical
problem for `[data-bg]` blocks and gives `parked` the same Y scale as wagons.
`H` is **0 for scripts**: a `<script>` box is `display:none`, so the trigger is
the script's own line. `end` therefore means "the line the author put the tag on
has left the top of the screen" — and the author moves the trigger by moving the
tag (last line of the topic = "topic is over"). No section-height heuristics.
`view`/`center` require the anchor to still overlap the viewport, which is what
makes `skip` distinguishable from `end` after a flick.

## State & Frame
Preallocated per anchor: `Uint8Array flags` of `SEEN_VIEW|SEEN_CENTER|SEEN_PARKED|SEEN_END|SEEN_SKIP`,
plus `Int32Array next` (compiled function index list head). No per-frame object
literals: firing walks a flat `Int32Array` linked list (`fnNext[k]`).
```js
for (let i = 0; i < n; i++) {
	const d = y[i] - scrollY;
	if (d < vh)        { if (!(f[i]&1)) { f[i]|=1; fire(0,i); } }
	if (d < vh * 0.5)  { if (!(f[i]&2)) { f[i]|=2; fire(1,i); } }
	if (d + h[i] < 0)  { if (!(f[i]&8)) { f[i]|=8; fire(3,i);
	                       if (!(f[i]&1) && !(f[i]&16)) { f[i]|=16; fire(4,i); } } }
	else if (f[i]&8) f[i]&=~8;                 // re-entered from top: re-arm end,
	                                       // view/center stay latched (no spam)
	if (parkedOk(i) && !(f[i]&4)) { f[i]|=4; fire(2,i); }

}
```
- Set on the forward edge, cleared only after `hysteresis` px of clear space on
  the *opposite* side (`d > vh + 40` clears `view`; `d > vh*0.5 + 40` clears
  `center`). Hysteresis on reset only — on the set side it would delay events.
- `end` is cleared as soon as the anchor is back in view, and `view`/`center`/
  `skip` are then pre-consumed, so scrolling up and down across the top edge
  does not spam `view` on every re-entry. `parked` is one-shot per pass: **not**
  cleared on unpark (`pos != 0`), so reverse scroll stays silent when the wagon
  parks again on the way up; it **is** re-armed when the script leaves through
  the bottom (`d > vh + hysteresis`), so a second forward read can fire it.
- Full-skip burst on load is a real bug (browser scroll restoration or a
  mid-document `#hash`): at `init`, flags for anchors already past are
  pre-set to `VIEW|CENTER|PARKED|END|SKIP` and nothing fires. `?vnsreplay=1`
  disables that pre-fill for testing, and `refresh()` re-applies it.
- O(A) integer compares per frame; A ≤ a few hundred is free. `frame()` runs
  after wagons' `pos[]` is written (subscriber order), so `parked` is accurate
  in the same frame — never fire from the scroll handler.

## Compilation (`init`/`refresh`)
```js
const code = el.textContent.trim();
if (!code) continue;
try { fn = new Function('VNS', 'detail', code); }     // page scope, no modules
catch (e) { console.error('VNS event script', e); continue; }
```
- One `Function` per (script, event) pair; store in `fnList`, index in the flat
  linked list. Errors are logged once with the anchor's Y; other scripts keep
  working.
- Body is left in the DOM (inert by type, and `view-source`/devtools stay
  honest); CSS hides it. A compiled `data-vns="view:1 skip:0"` attribute is
  written on fire for QA only, never read back — so `frame()` still does zero
  reads. Do not `el.remove()`: it destroys the author's document for no gain.
- `detail` is one reused frozen-shape object `{el, event, y, scrollY, wagon, morph}`
  mutated before each call (fired synchronously, so sharing is safe and keeps
  the "no allocation in the hot path" rule true).
- No sandbox illusion: snippets run with full page privileges. That is the
  design (author writes their own page); do not add `iframe`, `Worker`, or CSP
  handling for `file://`.

## Test Matrix (0.1 harness, `events=on`)
- Slow full pass: `view→center→parked→end` per chapter, exactly once each.
- Flick to bottom: skipped chapters fire `skip` + `end`, never `view`/`center`.
- Reverse: no new events while going up; re-entering from the top consumes
  `view` silently; leaving from the bottom again re-arms `view`.
- Two scripts on one event at one anchor: both run, DOM order (assert via
  `VNSlog` sequence).
- Free-floating script between two text lines outside any section: fires at its
  own Y (±2 px), independent of its neighbours' sections.
- Broken snippet (`let =`): one console error, its siblings still fire, wagons
  and morph unaffected.
- `wagons=0`: `parked` never fires (and with `parkedAsView=1` it fires with
  `view`) — assert exactly the configured behaviour.
- Reload mid-document: zero events fired at init.

## Acceptance Criteria
- [ ] Each declared event fires exactly once per forward pass at its documented
  threshold, ±2 px, verified by QA probe `events()`.
- [ ] `skip` fires only when `view` had not fired before `end`.
- [ ] Reverse scroll fires nothing new; re-crossing forward after the
  hysteresis margin fires again.
- [ ] A syntax/runtime error in one snippet is isolated: logged, others fire,
  wagon and style engines unaffected (frame loop never dies — check FPS).
- [ ] Works for section-bound and free-floating scripts alike.
- [ ] `file://`: executes with no CSP/module error; `?engine=0` leaves the
  snippets inert and visible in the DOM.
- [ ] No events fire on load regardless of restored scroll position.

## Pitfalls
- No `IntersectionObserver`: it reports layout position, so it cannot see
  `parked` (a transform state) and its callbacks are batched/coalesced — they
  would fire late and unreliably on flicks. `scrollY` math is exact and free.
- Never fire inside the scroll handler; batch in `frame()` after `pos[]`.
- Hysteresis belongs on the reset edge only.
- `type="txt"` must never be replaced with `type="text/plain"` + `eval`: same
  result, worse error line numbers.
- `refresh()` must re-collect and recompile: after regen, stale `Function`s
  pointing at removed nodes would fire on phantom anchors.
- Guard `VNSlog` absence: snippets must not hard-require harness globals to
  work in a real story page — document `detail` as the engine-provided API.
