# 0.2 — Wagon Engine + Shared Core

## Goal
Every `.bg` behaves as a train wagon tied to its DOM text position: rides 1:1
with scroll, parks at the viewport edge when it arrives, stays parked until the
next wagon below collides with its bottom and pushes it out. No overlap, no
jumps, fully reversible on reverse scroll, in any size mode, at any DOM depth.
This plan also lands `core`: one rAF loop, one anchor-measurement pass,
`refresh()`, and the subscriber API that 0.3/0.4 reuse.

## Non-goals
- No parallax: a wagon never moves faster or slower than its own text, except
  the lateral exit of `data-dir`, which is a different axis.
- No section tree: wagons are one global list in document order. A wagon is not
  owned by, clipped to, or sized by its `<section>` — an author may keep one
  wagon across sections or add a new one between two lines.
- No image-decode probing: wagon box size is CSS/`data-size`, never natural
  image size (see Size Modes — this removes a whole class of scroll glitch).

## DOM Contract
```html
<div class="bg" style="background-image: url('a.png')"
     data-mode="cover|contain|fixed|auto"   data-size="512" | "1024x768"
     data-dir="top|left|right|bottom"        data-static></div>

<section><h4>1</h4><div class="bg" …></div>free text<div class="bg"></div></section>
```
- `data-mode` default `cover`. `data-dir` default `top`. `data-static` = engine
  ignores the element entirely (escape hatch, and the only supported "off").
- `.bgwindow` is by contract an **in-flow** background block that never parks —
  the draft's "just a normal background" case. It is not an alias of `.bg`;
  treating them alike would remove the author's only way to say "no wagon".
- `data-size` sets the element box (`WxH`, or `W` square). Required for `auto`,
  optional for `fixed` (default 512).

## Core
```js
VNS.use({measure, arrange, frame})  // register controller, called in that order
VNS.refresh()               // mark dirty + poke one rAF; measure runs on that frame
VNS.step()                  // one manual frame (tests and QA probes drive this)
VNS.anchorY(el)             // document-order Y of el, marker-based, valid until refresh
VNS.wagons                  // {n, els, y, free, pos, ext, parked, dir}
VNS.debug                   // same arrays + wet (writes last frame) + styleN, eventN
VNS.stats                   // {frames, fires[5]}
VNS.options                 // {engine, wagons, morph, events, scope, hysteresis,
                            //  parkedAsView, replay} — all numeric, URL-flaggable
```
`VNS.use`, `VNS.step`, `VNS.refresh` and `VNS.anchorY` are **inert until boot**: with
`?engine=0` the object still exists but every entry point returns early, so a host
page can call `VNS.refresh()` unconditionally instead of feature-testing
`window.VNS` at every site. Disabling `wagons` still publishes an empty
`VNS.wagons` record for the same reason. `arrange()` is the third phase — see the
measure rule below: it reads the Y that core measured between `measure` and
`arrange`, which is the only safe place to resolve anything position-dependent.
- `scroll`/`resize`/`orientationchange` listeners are passive and only set
  `dirty=1` then `poke()`; `tick()` reads `window.scrollY`, runs `frame()`, and
  **stops the rAF chain when clean** (no permanent frame loop → no battery drain,
  no phantom work on a static page). Restart on next scroll.
- Passes are strictly separated: `measure()` may read layout (markers,
  `offsetHeight`); `frame()` writes `transform`/custom props only. One rAF, so
  style/wagons/events share one read phase and one write phase per scroll.
- `measure` order = registration order: wagons first (they create the markers
  that style/event anchors reuse), then morph, then events.
- `document.fonts.ready.then(refresh)` when available: font swap moves anchors.

## Anchor Measurement
`offsetTop` is **wrong** here (it is `offsetParent`-relative, and a `fixed`/
`transform`ed ancestor changes the origin) — and once a wagon is `fixed`/
`absolute` it has no in-flow position to read at all. Contract instead:
- Engine inserts `<i class="vns-a vns-w">` immediately **before** the element:
  `position:absolute;width:0;height:0;margin:0;padding:0;border:0;overflow:hidden;
  visibility:hidden;pointer-events:none`. Zero-size abspos contributes nothing
  to any line box or scroll height, so inserting it never shifts the text — that
  is why a marker beats `display:inline` or `display:block;height:0`.
- `Y = marker.getBoundingClientRect().top + scrollY`, all markers read in one
  loop after all DOM writes, so at most one forced layout per refresh.
- `el.__vnsA` caches the marker, `el.__vnsStamp` dedupes within one refresh;
  `refresh()` wipes the anchor table and re-creates indices (O(N), no Maps).
- Hoisting: each wagon is `layer.appendChild(el)` in anchor order — that fixes
  paint order (later wagon over earlier) and keeps layer order == array order.
  The wagon list is therefore rebuilt from markers already in `#app`
  (document order, includes hoisted wagons) **union** fresh `.bg` without a
  marker, not from a single `querySelectorAll` that would see layer children.

## Size Modes (pure CSS, mapped by attribute)
| mode | box | background-size |
|---|---|---|
| `cover` | `100vw × var(--vns-vh,100vh)` | `cover` |
| `contain` | `100vw × var(--vns-vh,100vh)` | `contain`, centred |
| `fixed` | `data-size` px, default 512 | `100% 100%` (art stretched into box) |
| `auto` | `data-size` px | `auto` (art unscaled, top-left) |
Engine sets `--vns-vh/--vns-vw` from `innerHeight/innerWidth` on the root, so
mobile URL-bar resize does not make every `cover` wagon taller than the screen
(the classic 100vh bug). A wagon shorter than the viewport intentionally
leaves a band of page colour below it — that is the point of `fixed`/`auto`.

## Core Math (the whole engine)
Preallocated arrays of length `N`: `y[N]` (anchor), `ext[N]` (box extent along
the scroll axis = `offsetHeight`), `free[N]`, `pos[N]`, `xoff[N]`, `dir[N]`,
`lastY[N]`, `lastX[N]`.

```js
// ride with text, park at the edge, and never overlap the wagon below.
// pos[i] = min(max(free[i],0), pos[i+1] - ext[i])   — sweep i = N-1..0
let prev = Infinity;
for (let i = n - 1; i >= 0; i--) {
	const park = free[i] > 0 ? free[i] : 0;      // 0 == parked at top edge
	const ceil = prev - ext[i];                   // contact with wagon i+1
	pos[i] = ceil < park ? ceil : park;
	prev = pos[i];
}
```
Why this and not "only push when parked": `min(park, ceil)` is a min of
continuous functions, so it is continuous and monotone in `scrollY` (no jump,
no hysteresis needed) and it is a *ceiling* — a wagon is never pushed below or
past its own anchor. Gating the push on `park==0` instead would keep perfect
anchor alignment but produce a `H−gap` pixel **jump** at the parking frame for
tight chapters, which the draft lists as a bug. Coupling is the accepted cost:
- gap ≥ `ext[i]` ⇒ wagon rides exactly on its text, parks at `y=0`, waits.
- gap < `ext[i]` ⇒ wagons are already in contact while riding; they form a
  continuous filmstrip and the upper one exits as soon as the lower one
  arrives. That is the wagon metaphor, not a bug — and it is why `anchorAlign`
  QA only asserts alignment where gap ≥ ext.
- Nothing pushes the last wagon: it parks at 0 and holds until document end.

`ext[i]` uses the element box height even for `contain`, whose visible art is
smaller: the chain is about *boxes*, so a `contain` wagon still blocks the
wagon below over its full screen-height box (that is what "no overlap" means
for a stretched wagon).

Exit vector, applied after the chain, still a pure function of `pos[i]`:
```js
top:    x = 0,      y = t            // slides up out of view (default)
left:   x = min(t,0), y = max(t,0)   // parks at top, then pushed sideways
right:  x = -min(t,0), y = max(t,0)
bottom: x = 0,      y = -t           // pushed down across the screen
```
`left`/`right` keep `y = max(t,0)`, i.e. they park at the edge and stay there
vertically, so a lateral exit never overlaps the wagon below it on the Y axis;
`bottom` deliberately crosses the screen (author asks for it), so `overlap()`
QA skips non-`top` wagons.

## Writes
```js
for (let i = 0; i < n; i++) {
	// …exit vector…
	if (y === lastY[i] && x === lastX[i]) continue;      // parked → zero work
	el.style.transform = 'translate3d(' + x + 'px,' + y + 'px,0)';
}
```
Quantised to whole pixels is not wanted (sub-pixel translate keeps motion
smooth); instead skip writes when the value is unchanged. `will-change:transform`
per wagon; `contain:layout paint` on the layer only. Note in findings: `N`
full-screen layers cost VRAM, so a long story should drop `will-change` or
window it to on-screen wagons.

## Lifecycle
- `boot()` on `DOMContentLoaded` (or immediately if already interactive), unless
  `?engine=0`.
- `VNS.options.wagons = 0` → wagons inert (no hoist, `.bg` stays in flow);
  0.3/0.4 still run, which is how "style works without wagons" is verified.
- `refresh()` is the only re-entry point; it must be safe to call mid-frame
  (guard with a `busy` flag; harness calls it after every regen).
- Regen while scrolled: anchors recomputed, `scrollY` untouched, one frame
  written. A wagon whose anchor vanished with the new content is dropped, not
  left parked.

## Test Matrix (0.1 harness)
- `gap`: `same` baseline; `mixed` (the parking/push bugs); `zero`/`tight`
  (coupled chain, no premature parking); `huge` (long holds at the edge).
- Mode `mixed` with 256/512/1024 interleaved — no overlap, no missed park.
- Two consecutive `.bg` with no text between: second pushes first, motion still
  1:1, no jump.
- `nest=flat`: `.bg` between loose text nodes, outside any section — identical
  behaviour to `nest=section`.
- Reverse scroll fast and slow: 10 sampled `scrollY` identical both directions.
- `resize` viewport while a wagon is parked: heights recomputed, nothing stuck.
- `data-dir=left` wagon: parks at top, slides left on contact, no Y overlap.
- Document ends before last wagon can park (no `.tail`): engine must not
  fake a park; with `.tail` it must park cleanly.

## Acceptance Criteria
- [ ] `reversibility()` passes: byte-identical transforms for equal `scrollY`
  going down and up, at 10 positions, all modes.
- [ ] `overlap()` passes for `data-dir=top` wagons at all sampled positions.
- [ ] `anchorAlign()` passes: while riding, wagon top == its marker line ±1 px;
  once parked, `y == 0` until contact; ±1 px at the contact frame.
- [ ] `jump()` passes: per-frame |Δtransform − ΔscrollY| ≤ 1 px while riding,
  Δtransform == 0 while parked.
- [ ] Last wagon parks and holds at `top:0` to the bottom of the document
  (nothing pushes it).
- [ ] `frame()` allocates nothing and reads nothing: verified by code review +
  `VNS.debug.frames` counter showing 0 work when idle (rAF chain stopped).
- [ ] All four modes interleaved, `file://`, no network, no image decode
  dependency.

## Pitfalls
- Never set `top`/`left` in `frame()` — only `transform`. Writing layout
  properties invalidates the anchors you measured → drift → "wagon crawls".
- Do not read `getBoundingClientRect` of the **wagon** for its anchor: it is
  transformed. Read the marker.
- Do not tie a wagon to `<section>` bounds for order, size, or lifetime.
- Push must use the already-resolved `pos[i+1]`, not `free[i+1]`, or a chain of
  3+ wagons pushes incorrectly (only the last gap is respected).
- Measuring `Y` inside `frame()` (no markers) → self-referential drift.
- `contain:paint` on the layer is safe; `contain:paint`/`transform` on an
  **ancestor of a fixed element** is the silent killer the hoist protects from.
- Keep `#vns-layer` out of `#app`, else `#app{position:relative;z-index:1}`
  repaints over it and every wagon disappears.

## Open Decisions (resolved, keep as-is)
- Size source of truth is `data-mode` + CSS mapping; computed
  `background-size` is never parsed. `auto` means "author-provided size", not
  "natural image size" — chosen deliberately so a `file://` page with SVG data
  URIs needs zero async measurement.
- `data-dir` names the *exit* direction, not a scroll direction.
