# 0.2 — Background Wagon Engine

## Goal
Make every `.bg` behave as a train wagon tied to its DOM text position:
moves 1:1 with scroll, parks at `top:0` (or `left:0` etc) when it hits
the viewport edge, stays there until the next wagon pushes it off. No
overlap, no jumps, fully reversible on reverse scroll, regardless of size
mode or free DOM placement.

## Non-goals
- No parallax (faster/slower than scroll) except for lateral `data-dir`
  pushes where push axis differs from scroll axis.
- No strict SECTION tree. Wagons are global ordered list by document
  order, not per-section.
- Not handling zoom pinch beyond `resize` recompute.

## DOM Contract
```html
<div class="bg" style="background-image: url('...')"
     data-mode="cover|contain|fixed|original"
     data-dir="top|bottom|left|right"></div>

<section><h4>1</h4><div class="bg" ...></div>free text<div class="bg"></div></section>
free text outside sections is legal
```
- `.bg` — positioned `position:fixed; top:0; left:0; will-change:transform`
  and moved only via `transform: translate3d(x,y,0)`.
- `.bgwindow` variant from draft treated as alias to `.bg` (same engine).
- Anchor = element's placeholder `offsetTop` in document flow before
  fixed-position upgrade. A zero-height placeholder `<i data-anchor>` is
  inserted at original location to retain document height and to read
  `Y[i]` without layout shift.
- Size sources:
  - `cover` — `100vh × 100vw`, `background-size:cover`
  - `contain` — `100vh × 100vw`, `background-size:contain`, centred
  - `fixed` — explicit `width/height` from inline style or `data-w/data-h`
  - `original` — SVG/natural size; `background-size:auto`, element sized
    to image natural dims (fallback 512)
- `data-dir` default `top` (pushed upward off screen). `left`/`right`/
  `bottom` mean wagon exits toward that edge when pushed; parked position
  stays at 0 on that axis.

## Core Algorithm
Preallocate once, mutate per frame. No `{}`/`[]`/string concat in rAF.

State arrays length `N`: `Y[N]`, `H[N]`, `W[N]`, `dir[N]`, `free[N]`,
`top[N]` (or `x[N]` for lateral). `viewport Hv, Wv`.

Per frame (rAF, passive scroll listener only sets `dirty`):
```
scrollY = window.scrollY
for i: free[i] = Y[i] - scrollY    // where text would be

// backwards sweep: prevent overlap, enforce parking
top[N-1] = clampPark(free[N-1])   // clampPark = free<=0 ? 0 : free  (for dir top)
for i = N-2 .. 0:
	park = free[i] <= 0 ? 0 : free[i]
	push = top[i+1] - H[i]        // next wagon's top minus my height
	top[i] = push < park ? push : park
// for dir left/right: analogous on x axis, y stays = parkY
// dir bottom: park at bottom edge, push downward

// write
for i: el[i].style.transform = 'translate3d('+x[i]+'px,'+top[i]+'px,0)'
```
Why this math:
- `park` pins wagon at viewport edge once its text hits top.
- `push` is collision constraint `top[i]+H[i] <= top[i+1]` (no overlap).
- `min(park, push)` lets push win when next wagon collides, pulling
  parked wagon off screen negatively. When gap exists, park wins.
- Pure function of `scrollY` → reversible, no hysteresis.

Horizontal push variant (`data-dir=left`):
- Park position is `(0, 0)` same as vertical.
- Push moves on X: `x[i] = min(0, x[i+1]-W[i])` once `top[i+1] <= H[i]`
  threshold, while `y[i]` stays parked at 0. Implement as separate
  axis lerp triggered by collision.

Viewport coverage note: wagons with `H[i] < Hv` leave visible gap below
parked wagon — intentional; body background shows through. `cover` wagons
fill screen.

## Lifecycle
- `init()` — collect `document.querySelectorAll('.bg,.bgwindow')` in
  document order, insert placeholders, read `Y/H/W/dir`, allocate arrays,
  bind `scroll` (passive) + `resize` + `load`.
- `refresh()` — re-collect and re-measure (called by harness after regen
  and on resize). Debounced 50 ms.
- `frame()` — rAF loop, bails if `!dirty` (scroll unchanged) but still
  checks resize dirty.
- Lazy images: if `original` size not yet known, use placeholder 512,
  re-measure on `img.onload` / `onload` of background image via
  `new Image().src` probe; second probe updates `H[i]` and marks dirty.
  No scroll glitch because placeholder size already reserves wagon slot;
  correction is at most one frame.

## Performance & Style
- Single tab indent, flat helpers, early returns.
- Reuse `Float32Array` or plain arrays allocated once; never `new` in
  `frame`.
- Read phase (measure `Y`, `scrollY`) before write phase (transforms).
- `will-change:transform`, `contain:layout paint` on `.bg`.
- `const $ = id => document.getElementById(id)` per AGENTS.

## Test Matrix (use 0.1 harness)
- Mixed gaps (tiny/mixed/huge) — proves parking holds without premature push.
- Same-size chapters — baseline, should still park.
- 512 vs 1024 vs cover heights interleaved — no overlap/miss.
- Two consecutive wagons with no text between — second immediately pushes first; must still be 1:1.
- Free placement: `.bg` between loose text nodes and inside sections — same behavior.
- Reverse scroll fast and slow — position at same `scrollY` identical both directions.
- Resize viewport — heights recomputed, no stuck wagon.
- `data-dir=left` wagon — parks at top, then slides left when next arrives (visual check, no overlap on Y).

## Acceptance Criteria
- [ ] Wagon whose anchor at `Y` reaches top stops at `top==0` and stays
  until next wagon's top touches its bottom.
- [ ] No two wagons ever overlap (except intentional lateral exit).
- [ ] Anchor alignment: while not parked, wagon's top edge coincides with
  its placeholder text line (±1 px, before transform).
- [ ] Fast scroll and reverse scroll produce identical layout for same
  `scrollY` (sample 10 scroll positions both directions).
- [ ] No jump >1 px between frames at 60 fps during continuous scroll
  (check transform delta).
- [ ] All four size modes work interleaved without overlap/park miss.
- [ ] `file://` with no network: gradients/SVG wagons behave identically.

## Pitfalls From Draft
- Fix: never set `top` via layout; only `transform`. Otherwise anchor
  measurement shifts.
- Fix: do not tie wagons to `<section>` bounds — global order only.
- Fix: push uses `top[i+1]-H[i]`, not `free[i+1]-H[i]` — must use already
  resolved `top[i+1]` so chain of 3+ wagons pushes correctly.
- Common glitch: recomputing `Y` inside rAF without placeholder → drift.
  Use placeholders.

## Open Decision
Background-size source of truth: prefer `data-mode` with CSS mapping
(`.bg[data-mode=cover]{background-size:cover}`) over parsing
`background-size` string. Allow both: if `data-mode` missing infer from
computed `background-size`. Document in harness controls.
