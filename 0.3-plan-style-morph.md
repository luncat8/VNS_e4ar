# 0.3 — Style / Theme Morph Engine

## Goal
Page theme (background colour, text colour, class-driven look of page, menu and
vignette) morphs smoothly between scroll anchors — like a sunset or opening a
door onto a bright room: continuous, interactive, reversible, never a blink.
Author marks anchors declaratively; no per-chapter JS.

## Non-goals
- Not a CSS-in-JS framework, no shader, no per-pixel work.
- No timeline editor: anchors are just attributes on elements.
- Does not animate `background-image`, `box-shadow` blur, or any property whose
  transition repaints the whole text layer per frame.

## DOM Contract
```html
<section data-bg="#0b1020" data-fg="#e8e6e1" data-style="night">
<div class="bg" data-bg="#ffe8a0" data-style="sunset" data-range="180">
<p data-style="compact">text</p>
```
- `data-bg` — page colour (`#rgb`, `#rrggbb`, `rgb()`/`rgba()`), or any CSS
  paint value that does not parse as a colour.
- `data-fg` — text colour.
- `data-style` — space-separated class names applied to `<html>`.
- `data-range="PX"` — how many px *before* this anchor the morph runs, i.e.
  the morph **completes at the anchor** and then holds. Default
  `min(interval, --vns-vh * 0.6)`.
- Free placement: collected by `querySelectorAll('[data-bg],[data-fg],[data-style]')`
  in document order, never by section traversal. A style anchor may be the same
  element as a wagon (`.bg` with both `background-image` and `data-bg`).

## Architecture
Second `VNS.use()` subscriber. No rAF of its own, no scroll listener, no
measurement in `frame()`: it uses `VNS.anchorY(el)` from the shared pass, so a
`.bg` style anchor gets the wagon's marker (its own rect is transformed and
would be wrong — this is the trap in this plan).
State, one flat `Int16Array` per channel set, all preallocated at `measure`:
`ay[]`, `br/bg/bb[]`, `fr/fg_/fb[]` + `hasBg[]/hasFg[]` presence bytes,
`range[]`, and `cls[]` (plain array of strings, only read at class swap).

## Per frame
```js
const c = scrollY + vh * 0.5;              // the reading line — ONE reference
const i = lastIndexLE(ay, c);              // -1 → before first anchor
if (i >= n - 1) { t = 1; j = n - 1; } else { j = i + 1;
	t = ease(clamp((c - (ay[j] - range[j])) / range[j], 0, 1)); }
// hold previous colour when an anchor omits a channel
if (hasBg[j]) col = mix(colorOf(i), colorOf(j), t) else col = colorOf(i);
setVar('--vns-bg', col); setVar('--vns-fg', col2); setVar('--vns-t', t);   // quantised: authors may key off it
```
- Everything — segment choice, lerp, class swap — uses the same `c`. Mixing a
  centre-based index with a raw-`scrollY` progress (as an earlier draft did)
  leaves `t` unable to reach 1 before the segment ends → colour **snaps** at
  every anchor. Morph completing *at* `ay[j]` makes `t==1` coincide exactly
  with the class swap and with holding, so no discontinuity is possible.
- `i < 0` → fully hold anchor 0; `i == n-1` → fully hold the last anchor.
- `ease(t) = t<.5 ? 2t² : 1-(2-2t)²/2` (easeInOutQuad): cheap, no harsh start.
- Colour mixing is done in linear light with two 256-entry LUTs
  (`srgbToLinear`, `linearToSrgb`) built once at load; sRGB-space lerp visibly
  darkens mid-transition (the "muddy purple" between blue and red).
- Writes are quantised: keep `lastBg/lastFg` ints, `setProperty` only when the
  8-bit value changed. Steady state = zero string concat, zero style dirtying.

## Classes
- The engine owns a class list on `<html>`: it records the names it added,
  removes exactly those, adds the current segment's. Author classes elsewhere
  are untouched.
- One segment wins: `data-style` on the last passed anchor replaces the engine
  set. To keep a class for several chapters, re-state it (documented). This is
  deliberate: "one active at a time" is only implementable if the model is
  *segment → set*, and it stays fully reversible without a stack.
- Swap exactly when `c >= ay[j]` (`t` reaches 1), so class change and colour
  arrival are the same instant.
- Author CSS provides the look; engine only names it:
```css
html{background:var(--vns-bg,#fff);color:var(--vns-fg,#111)}
html.fog #app{filter:contrast(.94) saturate(.8)}
html.night .n{outline:2px solid #6cf}
```
- **No `transition` on `--vns-bg`/`--vns-fg`/`background-color`**: the lerp is
  the smoothing; a CSS transition on top adds lag, fights the per-frame write,
  and makes reversibility time-dependent. Transition only class-driven props
  (`filter`, `opacity`), and only if the author wants it.

## Interaction With Wagons
- Wagons paint in `#vns-layer` at `z-index:0`, `#app` at `z-index:1`; the page
  colour lives on `html` (never `#app`, which would cover the wagons). A
`cover` wagon hides the page colour while parked — that is correct layering,
  and `fixed`/`auto` wagons let the morphing colour show around them.
- Style lerp continues while a wagon holds at the edge, so "cold→warm while the
  picture stays" works with no coupling between the two controllers.
- `filter` on `#app` is now safe *because* wagons are hoisted out of it; it is
  still a full-layer raster, so note the cost in findings.

## Test Matrix (extends 0.1 harness, `style=on`)
- Colour cycle red→blue→green per chapter, slow scroll: glide, no step.
- `data-range="80"` vs `"800"`: quick settle vs whole-chapter glide.
- Free-placed `data-bg` between two text lines (no section): still lerps at its
  own Y; the section's own anchor keeps holding before it.
- Anchor with only `data-fg` (no `data-bg`): colour holds previous, no flash to
  default.
- `cover` wagon + `data-bg` on the same element: both apply, no double transform.
- Reverse scroll: colours retrace exactly (QA `reversibility()` extended to read
  `getComputedStyle(html).backgroundColor` at the same 10 positions).
- `wagons=0`: morph still runs from `core` alone (this is the standalone check).
- Regen with an extra anchor: `refresh()` picks it up, no reload.

## Acceptance Criteria
- [ ] Between two anchors, `--vns-bg` moves monotonically and reaches the
  target colour exactly at the anchor; no sample position shows a step > 1/255
  per frame at 60 fps.
- [ ] No colour snap at any anchor crossing (verify `c = ay[j]-1` vs `ay[j]`
  differ by ≤ `1/range` of the gradient).
- [ ] `data-style` class becomes active at `c >= ay[j]` ±2 px, previous engine
  classes removed; engine never removes a class it did not add.
- [ ] Zero layout shift from style change (only paint: colour, filter, opacity).
- [ ] Works with wagons on and off; works when no `.bg` exists at all.
- [ ] `reversibility()` passes on computed colours.
- [ ] Idle cost is zero: no `setProperty` calls while `scrollY` is unchanged.

## Pitfalls
- Do not animate `background-image`; do not lerp gradients. A non-colour
  `data-bg` value is assigned verbatim at the boundary (instant, class-like) —
  documented, because gradient interpolation would need a stop table.
- Do not read `getComputedStyle` per frame (forced style recalc) — the engine
  compares against its own last-written integers.
- Guard missing anchors: `hasBg[i]` false → hold, never mix with `NaN`
  (`NaN` in a custom prop silently kills the whole theme, which is nasty to
  debug).
- `data-range` shorter than 1 px must clamp to 1, not divide by zero.
- Collect via attribute selector in document order; section traversal silently
  drops free-floating anchors, which is the feature.

## Future Hook
0.4 may expose `event="style:N"` (fires at morph progress N%) once authors ask
for it; not needed now — `center` on the same anchor already correlates.
