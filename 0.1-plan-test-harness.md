# 0.1 — Test Harness & Content Generator

## Goal
Standalone `index.html` that is the development and manual QA surface for
all engine features. Generates text and visuals on the fly, zero network,
`file://` friendly, no build. Lets developer and user see every
combination of chapter size, background size and stretch mode.

## Non-goals
- Not a production template. Keep it noisy and diagnostic.
- No lorem ipsum. Text must be position-readable (`R`, `1`, `3`, chapter
  labels, ruler marks) so scroll position and wagon identity are obvious
  without reading.

## Architecture
- Single `index.html` with classic `<script>` tags. No modules, no imports.
- All generation in one inline script guarded for Node:
  `if(typeof module!=='undefined')return;`
- Controls rendered as `<form id="gen">` at top; buttons regenerate without
  reload. State in `location.hash` so refresh keeps config.
- Use `<section>` tree freely but also test free-floating text nodes —
  generator must produce both variants to prove engine does not require
  strict SECTION nesting.

## DOM Contract
```html
<div id="app"></div>
<form id="gen">
  <label>chapters <input id="n" type="range" min="1" max="12"></label>
  <label>gap <select id="gap"><option>tiny<option>mixed<option>huge</select></label>
  <label>mode <select id="bgmode"><option>cover<option>contain<option>fixed<option>original</select></label>
  <button id="reg">regenerate</button>
</form>
```
Generator appends into `#app`. Every background is:
```html
<div class="bg" style="background-image: ..."></div>
```
No external URLs. Patterns produced via:
- `linear-gradient(...)` / `radial-gradient(...)`
- inline `data:` SVG (`<svg>…</svg>` URI-encoded)
- `<canvas>`-generated data URL for noise/checker (once at setup)

## Generation Rules
- Chapters: `1<br>1<br>…` blocks with heading `<h4 class="n">1</h4>`
  inside optional `<section>`. Length varies per chapter: tiny 20 lines,
  medium 80, huge 200 — mixed mode randomises to expose parking/push bugs
  (same-size chapters hide bugs).
- After each heading emit an optional `.bg` then varying text gap then
  maybe another `.bg` free-placed between lines — proves free placement.
- Labels: `R<br>R<br>R<br> after RED image` — colour letter repeats so you
  can tell which background the text belongs to.
- Background palette: 6 gradients (red, blue, green, yellow, purple, checker)
  cycling. Each `.bg` gets `data-mode` (`cover|contain|fixed|original`)
  and `data-dir` occasionally (`left`).
- Sizes matrix: in `cover` → 100vh/100vw; `contain` → contain centred;
  `fixed` → `512px` or `1024px` square via inline `width/height`;
  `original` → natural SVG size (256,512,1024) via `background-size:auto`.
- Emit ruler on left edge: fixed `position:fixed` vertical marks every
  100vh + dynamic marker for `scrollY`.

## Diagnostics Overlay
- Fixed top-right panel: `scrollY`, `viewport H`, `#bg`, active wagon
  index, parked flags.
- Optional wireframes: toggle outlines for `.bg` natural anchor
  (dashed) vs rendered `transform` box (solid).
- FPS counter via `requestAnimationFrame` delta, no allocations in hot
  path.

## Acceptance Criteria
- [ ] Opening `index.html` via `file://` shows controls and generated
  story without console errors or network requests.
- [ ] Changing chapters/gap/mode and pressing Regenerate rebuilds DOM in
  <100 ms for 12 chapters, scroll position reset to 0.
- [ ] Every chapter label and R-run is visibly distinct; you can tell
  scroll position by reading text alone.
- [ ] Same config with `mixed` gaps exposes all wagon bugs listed in
  draft (overlap, gap, jump) when engine is absent — and hides them when
  0.2 engine is enabled.
- [ ] No external images; view-source shows all visuals as gradients or
  `data:` URIs.

## Pitfalls To Avoid
- Do not rely on external image load timing — use gradients/SVG so
  size is known synchronously for 0.2.
- Avoid layout thrash: generate string via array join, single
  `innerHTML` assignment, then one reflow.
- Keep generation deterministic for given seed (hash) so bug report =
  hash string.

## Next Plan Dependency
0.2 Wagon Engine consumes the DOM produced here. Harness must expose
`window.VNS_refresh()` to recompute anchors after regeneration and on
`resize`.
