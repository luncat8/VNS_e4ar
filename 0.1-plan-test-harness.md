# 0.1 — Test Harness & Content Generator

## Goal
`index.html` + `harness.js`: the single development and manual-QA surface for
every engine feature. Generates text and visuals on the fly, zero network,
`file://` friendly, no build. Must show every combination of chapter length,
gap, background size and stretch mode — and must also provide *automated* QA
probes so that 0.2–0.4 acceptance criteria are machine-checked, not eyeballed.

## Non-goals
- Not a production template. Keep it noisy and diagnostic.
- No lorem ipsum. Text must be position-readable (`R`, `3·12`, chapter labels,
  ruler ticks) so scroll position and wagon identity are obvious at a glance.
- No canvas-generated textures: inline SVG data URIs and CSS gradients are
  enough, synchronous, and give 0.2 a known box size without image decode.

## Architecture
- Classic `<script src="vns.js">` then `<script src="harness.js">`. No modules.
- Harness must work with the engine absent (`?engine=0`) and must never assume
  `VNS` exists: every call is `VNS && VNS.refresh()`.
- All DOM built as one string, single `app.innerHTML = parts.join('')`, then one
  reflow. No per-node `createElement` loops.
- Config lives in `location.hash` (written with `history.replaceState` in a
  `try/catch`, because `file://` may refuse it — fall back to plain `hash=`).
  `seed` is part of the hash so a bug report is a copy-pasteable hash.
- Deterministic generation: `mulberry32(seed)` PRNG, no `Math.random()`.

## Controls (`<form id="gen">`)
| id | values | meaning |
|---|---|---|
| `n` | 1..12 | chapter count |
| `len` | `tiny` 18 lines, `mono` 60, `huge` 220 | lines per chapter |
| `gap` | `zero` none, `same` fixed, `mixed` seeded random, `huge` >1 wagon | text lines between a heading and its `.bg` — the axis that exposes parking bugs |
| `mode` | `cover` `contain` `fixed` `auto` `mixed` | wagon `data-mode` |
| `size` | `256` `512` `1024` `mixed` | `data-size` for `fixed`/`auto` |
| `dir` | `none` `mixed` | sprinkle `data-dir="left\|right\|bottom"` |
| `nest` | `section` `flat` `both` | wrap chapters in `<section>` or emit loose nodes — proves no section tree is required |
| `style` | `off` `on` | per-chapter `data-bg`/`data-fg`/`data-style` + `data-range` |
| `events` | `off` `on` | `script type="txt"` blocks per chapter |
| `static` | `off` `on` | emit `.bgwindow`/`data-static` escape-hatch samples |
| preset | `mixed` `mono` `tight` `draft` | `tight` = wagons with zero gap (coupled train); `draft` = the snippet from the draft file, verbatim |
Buttons: `regen` `top` `bottom` `next ch` `prev ch` `autoscroll` `QA: all`.
Checkboxes: `wireframes` `show engine state`.

## Generated DOM
Per chapter `k` with colour name `C` (red/blue/green/yellow/purple/checker):
```html
<section data-bg="#…" data-fg="#…" data-style="night" data-range="240">
  <h4 class="n">3</h4>
  3·0<br>3·1<br>…                       <!-- line number = position proof -->
  <div class="bg" data-mode="cover" data-size="512" data-dir="left"
       style="background-image:url('data:image/svg+xml,…')" data-bg="#0f8">
     bg 7 · cover · 512                 <!-- label rides with the wagon -->
  </div>
  R<br>R<br>R                           <!-- colour run after its image -->
  3·40<br>…
  <script type="txt" event="view">VNSlog("ch3 view")</script>
</section>
```
Rules:
- `.bg` is placed **after** its heading and text gap, and sometimes a second one
  free-floating between two lines — the free-placement case.
- Chapter length varies with `mixed`, because equal-size chapters hide
  parking/push bugs (every wagon behaves identically).
- Trailing spacer `<div class="tail"></div>` with `height:100vh`: without it the
  last wagon can never reach the top edge and can never park — a real bug class
  that must not be confused with an engine fault.
- `data-bg` colour cycle red→blue→green→yellow→purple→checker; `R<br>` runs use
  the same letter as the colour so text and image are matched by eye.

## Visuals (no external URLs)
- `linear-gradient()` / `radial-gradient()` strings for `cover`/`contain`.
- `svgURI(w,h,label)` → `url("data:image/svg+xml,<encoded>")` with explicit
  `width`/`height` attributes, a 1px border, a checker band and the wagon index
  at each corner — so scaling, offset and edge contact are all visible.
  Encoding is `encodeURIComponent` (a raw `#` in a fill colour truncates the
  URI), and the whole URI is wrapped in `url("…")` with double quotes because
  the HTML attribute is single-quoted.
- Every visual must have a synchronous, known size. Nothing may depend on
  image load timing.

## Diagnostics overlay (`#diag`, fixed, `pointer-events:none` on the rail)
Updated at 10 Hz, never per frame:
`scrollY`, `innerHeight`, `--vns-vh`, document height, `#bg`, wagon count,
active wagon index, parked count, pushed count, FPS + worst frame ms,
event fire counters, and a PASS/FAIL list from the QA probes.
Reads engine state through `VNS.debug` (`{free, pos, ext, y, els, n}`) — the
engine publishes those arrays so the overlay is a view, not a second model.
Left rail: fixed tick marks every 100 px of viewport + a marker at `scrollY`.
Wireframe mode: for each wagon, a dashed 1px outline at its anchor Y (where its
text is) and a solid outline at its rendered box — the difference *is* the bug
report. Wireframes use `getBoundingClientRect` and only run when enabled.

## QA probes (the mechanical part of every later plan's criteria)
All are async: they drive `window.scrollTo`, wait 2 rAF, read
`el.style.transform` (inline value = the engine's output verbatim, no computed
style cost). Where a probe needs a *sampling clock* it scrolls and calls
`VNS.step()` synchronously instead of using `autoscroll` — an rAF animation is a
human aid, not a measurement source. Probes parse the transform numbers with a
tolerant regex rather than comparing formatted strings: engines normalize
`translate3d` spacing differently. They must also survive a DOM with no layout
(jsdom: every box 0×0) by reporting `skipped`/`n/a` rows instead of throwing,
which is what makes them headless-testable.
- `reversibility()` — walk 10 evenly spaced `scrollY` values down, then up;
  assert the transform string per wagon is byte-identical for equal `scrollY`.
- `overlap()` — at each of 10 positions assert `y[i] + h[i] <= y[i+1] + 1`
  for consecutive wagons whose `data-dir` is `top` (lateral exits exempt).
- `anchorAlign()` — for each wagon with gap to next ≥ its own height, scroll so
  `free == 0` and assert `y == 0` (±1 px), and at `free == 300` assert
  `y == 300` (±1 px).
- `jump()` — during `autoscroll` at fixed px/frame record max
  `|Δtransform − ΔscrollY|` per wagon; assert ≤ 1 px (parked wagons must have
  Δtransform == 0).
- `events()` — slow full pass: assert per chapter order `view→center→parked→end`
  with count 1 each; then `scrollTo(bottom)` in one flick: assert `skip` fired
  and `view` did not for chapters fully jumped.
Each probe appends `{name, ok, detail}` and logs `console.info('VNS QA', …)`.
Harness installs `window.VNSlog = msg => (log.push(msg), …)` and event scripts
call it, so the panel can count fires without touching `console`.

## Acceptance Criteria
- [ ] Opening `index.html` by `file://` shows controls and generated story, no
  console errors, zero network requests (verify in devtools Network tab).
- [ ] Changing any control and pressing `regen` rebuilds 12 chapters in
  <100 ms and resets `scrollY` to 0.
- [ ] `?engine=0` still renders readable prose with in-flow background blocks —
  the no-engine baseline is visibly different from a broken engine.
- [ ] Every chapter label, line number and colour run is distinguishable;
  you can state `scrollY` ±50 px by reading text alone.
- [ ] `view-source` contains no external URLs: all visuals are gradients or
  `data:image/svg+xml`.
- [ ] Same hash ⇒ identical DOM (byte-compare `#app.innerHTML` after two regens
  with the same hash) so a bug report is just the hash.
- [ ] `reversibility`, `overlap`, `anchorAlign`, `jump` all run from the panel
  and print PASS/FAIL. With no engine they trivially pass (nothing moves);
  with 0.2 they must pass for real — that is 0.2's gate.

## Pitfalls
- Determinism over realism: seeded PRNG, no `Math.random`, no `Date` in output.
- Do not put `transform`/`filter`/`will-change` on `#app` ancestors — see
  overview Layout Contract; it silently breaks 0.2.
- `harness.css` must not set `background` on `#app` (covers wagons at
  `z-index:0`). Page colour goes on `html` — 0.3 drives it.
- Keep `#gen`/`#diag` outside `#app`: engine collects from `#app`, and the
  fixed panels must not be hoisted or measured as anchors.
- Do not scroll with `behavior:'smooth'` inside QA probes — it never settles and
  falsifies results. Use instant `scrollTo` + 2 rAF.

## Next Plan Dependency
0.2 consumes this DOM. Harness exposes `VNS.refresh()` on regen/resize and
reads only `VNS.debug`; nothing in 0.1 depends on 0.2 internals beyond the
published contract.
